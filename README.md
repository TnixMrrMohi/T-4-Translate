# T-4 Translate

برنامهٔ در حال توسعه برای ترجمه و ویرایش محلی مانگا و وب‌تون. وضعیت و تصمیم‌های پروژه در [نقشهٔ ساخت](docs/roadmap.md) آمده است.

## راه‌اندازی سریع روی سیستم خودتان

پیش‌نیاز: **Python 3.11+** و **Node.js 20 LTS**.

**ویندوز** (PowerShell در پوشهٔ پروژه):

```powershell
powershell -ExecutionPolicy Bypass -File .\run_t4_translate.ps1
```

**لینوکس / macOS**:

```bash
./run_t4_translate.sh
```

این اسکریپت‌ها به‌صورت خودکار محیط مجازی و وابستگی‌های بک‌اند را نصب می‌کنند، `npm ci` را اجرا می‌کنند، بک‌اند را روی `http://127.0.0.1:8000` و رابط را روی `http://127.0.0.1:5173` بالا می‌آورند، مرورگر را باز می‌کنند و با Enter / `Ctrl+C` هر دو سرویس را می‌بندند.

گزینه‌های مفید:

```powershell
# نصب OCR آزمایشی (RapidOCR؛ حدود چند صد مگابایت و چند دقیقه)
.\run_t4_translate.ps1 -InstallOcr
# تغییر پورت‌ها
.\run_t4_translate.ps1 -BackendPort 8010 -FrontendPort 5180
```

```bash
./run_t4_translate.sh --install-ocr
BACKEND_PORT=8010 FRONTEND_PORT=5180 ./run_t4_translate.sh
```

نکته‌ها:

- در ویندوز اگر پیام «اجرای اسکریپت غیرفعال است» دیدید، همان دستور `-ExecutionPolicy Bypass` بالا کافی است و نیازی به تغییر تنظیمات سیستم نیست.
- فایل‌های بارگذاری‌شده در `~/.t4-translate` (در ویندوز `%USERPROFILE%\.t4-translate`) ذخیره می‌شوند؛ با `T4_DATA_DIR` می‌توانید مسیر را عوض کنید.
- هر دو سرویس فقط روی `127.0.0.1` گوش می‌دهند و از شبکهٔ محلی قابل دسترس نیستند؛ این سرویس احراز هویت ندارد و نباید عمومی شود. برای اجرا از داخل کانتینر، `T4_DEV_HOST=0.0.0.0` را فقط در محیط ایزوله استفاده کنید.
- اگر پورت‌ها اشغال‌اند، اسکریپت با پیام مشخص متوقف می‌شود؛ با `-BackendPort` / `-FrontendPort` یا متغیرهای `BACKEND_PORT` / `FRONTEND_PORT` پورت دیگری بدهید.
- اجرای دستی همان مراحل، در بخش‌های زیر آمده است.

## اجرای پایهٔ بک‌اند

به Python 3.11 یا جدیدتر نیاز دارید:

```bash
cd backend
python -m venv .venv
# ویندوز: .venv\Scripts\activate
# لینوکس/macOS: source .venv/bin/activate
python -m pip install -e ".[test,render]"
python -m pytest
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

مسیر `/healthz` سلامت سرویس را نشان می‌دهد. این سرویس هستهٔ آزمایشی برنامه است؛ خروجی نهایی ترجمه هنوز پیاده‌سازی نشده است.

## اجرای رابط توسعه

در ترمینالی جدا، پس از اجرای بک‌اند:

```bash
cd frontend
npm ci
npm run dev
```

آدرس نمایش‌داده‌شده توسط Vite را در مرورگر باز کنید. رابط امکان ثبت تصویر، OCR و پاک‌سازی آزمایشی و ذخیرهٔ ترجمهٔ دستی را فراهم می‌کند. برای بررسی build رابط `npm run build` را اجرا کنید و برای تست‌های رابط `npm test` (Vitest + Testing Library؛ دیالوگ‌ها، حذف کار و مسیرهای تأیید/خطا). Vite درخواست‌های `/api` و `/healthz` را به `http://127.0.0.1:8000` پروکسی می‌کند؛ اگر بک‌اند را روی پورت دیگری اجرا کردید، `T4_BACKEND_URL=http://127.0.0.1:8010 npm run dev` را به کار ببرید. CI برای تست و ساخت نسخهٔ آزمایشی ویندوز تنظیم شده است؛ به‌روزرسانی خودکار هنوز پیاده‌سازی نشده است.

API آزمایشی `POST /api/jobs` تصویر معتبر را با وضعیت `uploaded` و زمان ساخت در پوشهٔ محلی کاربر ذخیره می‌کند؛ `GET /api/jobs/{jobId}` وضعیت ذخیره‌شده را برمی‌گرداند و `GET /api/jobs?limit=20` فهرست تازه‌ترین کارهای همان سیستم را می‌دهد (رابط از آن برای بازکردن کار قبلی استفاده می‌کند) و `DELETE /api/jobs/{jobId}` کار را با همهٔ فایل‌هایش پاک می‌کند. مسیر داده را می‌توان با `T4_DATA_DIR` تعیین کرد. هنوز صف یا پردازش واقعی وجود ندارد و نباید این سرویس را در معرض شبکه قرار داد.

## OCR آزمایشی (اختیاری)

برای آزمایش محلی، در محیط مجازی بک‌اند `python -m pip install -e '.[ocr-experimental]'` را اجرا کنید و سرویس را دوباره راه بیندازید. بستهٔ آزمایشی RapidOCR مدل‌های خود را همراه دارد؛ این روش هنوز نصب‌کنندهٔ نهایی مدل، مدیریت مجوز یا دانلود جداگانهٔ تأییدشده نیست. در لینوکس بدون رابط گرافیکی ممکن است کتابخانهٔ OpenCV به وابستگی‌های سیستم نیاز داشته باشد؛ در آن حالت به‌جای `opencv-python` از `opencv-python-headless` استفاده کنید (همان نسخه) تا خطای `libGL.so.1` رخ ندهد. پس از ثبت تصویر، دکمهٔ «اجرای OCR آزمایشی» متن خام و احتمالی را نمایش می‌دهد و پیش‌نمایش تصویر با کادر و شمارهٔ هر خط ساخته می‌شود (`GET /api/jobs/{jobId}/ocr-preview`) تا کیفیت تشخیص پیش از ترجمه بررسی شود. اجرای inference روی CPU و به‌صورت تک‌پردازش همزمان است؛ درخواست تا پایان پردازش باز می‌ماند. خروجی OCR در workspace ذخیره می‌شود. کیفیت، ترتیب و مختصات، به‌ویژه برای وب‌تون بلند، هنوز تأیید نشده و متن نیازمند بازبینی است.

بعد از OCR آزمایشی، متن شماره‌گذاری‌شده را می‌توان برای ترجمه کپی کرد و پاسخ شماره‌دار را در رابط ذخیره کرد. شماره‌های جاافتاده، تکراری و ناشناخته گزارش می‌شوند. اگر OCR پس از ترجمه تغییر کند، ذخیره بر اساس نسخهٔ قدیمی رد می‌شود.

## نمایش پیش‌نمایش‌ها (صفحه‌های بلند)

تصاویر وب‌تون می‌توانند بسیار بلند باشند (مثلاً ۱۵۰۰×۱۵۰۰۰). رابط دیگر تصویر کامل را داخل صفحه نمی‌گذارد؛ هر پیش‌نمایش (منبع، OCR، پاک‌سازی، رندر) به‌صورت یک **بندانگشتی ثابت‌اندازه** نمایش داده می‌شود (`GET /api/jobs/{jobId}/thumb/{source|ocr|clean|render}`، بزرگ‌ترین ضلع ۴۸۰ پیکسل با کش نسخه‌دار) و با کلیک، مودال تمام‌صفحه با زوم ۲۵٪ تا ۴۰۰٪، «عرض کامل» و «تناسب صفحه» باز می‌شود. برای صفحه‌های بلند (نسبت ارتفاع به عرض بیش از ۲٫۵) حالت پیش‌فرض «عرض کامل» با پیمایش عمودی است تا متن خوانا بماند. کلیدها: `Esc` بستن، `+`/`-` زوم، `0` بازنشانی.

## درج ترجمهٔ فارسی روی تصویر (آزمایشی)

افزونهٔ رندر با `python -m pip install -e ".[test,render]"` نصب می‌شود (یا همراه OCR آزمایشی). پس از ذخیرهٔ ترجمه، دکمهٔ «پاک‌سازی و درج ترجمه» اول ناحیه‌های ترجمه‌شده را پاک می‌کند و بعد متن فارسی را داخل همان کادرها می‌نویسد؛ با دکمهٔ «درج دوبارهٔ ترجمه» می‌توان بدون پاک‌سازی دوباره و پس از تغییر ترجمه، پیش‌نمایش را بازسازی کرد. مسیرها: `POST /api/jobs/{jobId}/render` و `GET /api/jobs/{jobId}/render`؛ نتیجه در workspace به‌صورت `render.png` ذخیره می‌شود و با تغییر OCR یا ترجمه منقضی می‌شود.

جزئیات فعلی: فونت وزیرمتن همراه مخزن است (قابل تغییر با `T4_FONT_PATH`)، اندازهٔ قلم تا جا شدن در کادر کوچک می‌شود، متن چندخطی می‌شود، رنگ متن بر اساس روشنایی پس‌زمینه انتخاب می‌شود و متن در مرکز کادر قرار می‌گیرد. چون Pillow در برخی محیط‌ها با RAQM ساخته نشده است، shaping با `arabic-reshaper` و bidi با `python-bidi` انجام می‌شود؛ نتیجه برای فارسی و متن سادهٔ ترکیبی درست است، اما kerning دقیق، تغییر شکل حروف فارسی (مثل «ی» و «ک») و کنترل کامل جهت‌ها را تضمین نمی‌کند. تنظیم دستی اندازه/جای متن و ویرایشگر کامل هنوز وجود ندارد.

پاک‌سازی کلاسیک آزمایشی در صورت نصب افزونهٔ OCR (و OpenCV) با دکمهٔ جداگانه قابل اجراست. فقط نواحی دارای ترجمه را هدف می‌گیرد و نواحی بدون ترجمه محافظت می‌شوند؛ نتیجهٔ آن PNG است و هنوز متن فارسی ندارد. روی تصویر نمونه، نتیجه آثار سفید قابل‌توجه دارد و برای خروجی نهایی مناسب نیست. تصاویر شفاف، دارای چرخش EXIF و بیش از ۲۵ میلیون پیکسل فعلاً در این مسیر پشتیبانی نمی‌شوند. برای پاک‌سازی باکیفیت و صفحات بلند به روش دیگری نیاز است.

## نسخهٔ آزمایشی ویندوز

پایپ‌لاین Windows build and tests پس از گذر تست‌ها یک artifact به نام `T4Translate-Windows-<commit>` می‌سازد. در GitHub به Actions، اجرای موفق و بخش Artifacts بروید؛ ZIP را دانلود و کامل استخراج کنید و `T4Translate.exe` را اجرا کنید. پوشهٔ استخراج‌شده را کامل نگه دارید؛ برنامه تک‌فایل نیست. WebView2 Runtime روی ویندوز لازم است. داده‌ها در `%LOCALAPPDATA%\T4Translate` قرار می‌گیرند و با جایگزینی پوشهٔ برنامه پاک نمی‌شوند. این بسته فعلاً امضای کد، نصب‌کننده و آپدیت خودکار ندارد و ممکن است Windows SmartScreen هشدار دهد؛ صرفاً نسخهٔ آزمایشی است. بسته‌های OCR فعلی همراه مدل هستند و مجوزهای توزیع باید قبل از انتشار عمومی بررسی شوند.

این مخزن خصوصی است؛ artifactها فقط با دسترسی به مخزن قابل دانلودند. برای آپدیت خودکار باید یک روش امن برای دریافت بسته از مخزن خصوصی یا یک کانال توزیع جداگانه تعیین شود؛ نباید کلید GitHub داخل برنامه قرار گیرد.
