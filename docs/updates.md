# به‌روزرسانی خودکار T-4 Translate

این سند می‌گوید برنامه چطور آپدیت می‌گیرد، چرا این کانال انتخاب شده، چه محدودیتی
روی GitHub وجود دارد و چطور یک ریلیز تازه منتشر می‌شود.

## چرا Release و نه Artifact؟

| | Release assets | Actions artifacts |
|---|---|---|
| دسترسی | `api.github.com/repos/{repo}/releases/latest` برای هر کسی با توکن خواندن | فقط با `actions:read` و API داخلی |
| آدرس | ثابت و قابل پیش‌بینی برای هر تگ | آدرس موقت، همراه با redirect و انقضا |
| عمر | تا وقتی ریلیز پاک نشود | ۳۰ روز (پیش‌فرض)، بعدش خطای ۴۱۰ |
| دلتا | می‌توان چند فایل کنار هم گذاشت (`update-manifest.json`، `update-<tag>.zip`) | همهٔ فایل‌های artifact با هم |

برای برنامه‌ای که ماه‌ها روی سیستم کاربر می‌ماند، آدرس ثابت و عمر نامحدود تعیین‌کننده
است؛ artifact برای انتقال بین jobهای CI خوب است، نه برای توزیع نسخه.
پس: **Release**.

## چه فایلی روی ریلیز می‌رود؟

- `T4Translate-<tag>-windows-x64.zip` — بستهٔ کامل (اولین نصب یا بازیابی).
- `update-manifest.json` — `{version, generatedAt, files:[{path,size,sha256}], removed:[...]}`.
- `update-<tag>.zip` — **فقط** فایل‌هایی که هششان نسبت به فهرست ریلیز قبلی عوض شده
  (به‌همراه فایل‌های تازه). فایل‌های دست‌نخورده دوباره وارد بسته نمی‌شوند.

`packaging/update_manifest.py` همین دو فایل را می‌سازد و در CI پیش از `gh release create`
اجرا می‌شود. فهرست ریلیز قبلی با `gh release download --pattern update-manifest.json`
گرفته می‌شود؛ اگر نباشد (اولین ریلیز) دلتا شامل همهٔ فایل‌هاست.

## مسیر آپدیت در برنامه

1. رابط هر `pollSeconds` (پیش‌فرض ۱۰ ثانیه) وضعیت را از **سرور محلی خود برنامه**
   (`GET /api/update/status`) می‌پرسد. این درخواست به GitHub نمی‌رود.
2. سرور فقط هر `checkSeconds` (پیش‌فرض ۳۰۰ ثانیه) یک بار GitHub را می‌پرسد
   (`releases/latest` + `ETag`). پاسخ ۳۰۴ یعنی «عوض نشده» و خطا حساب نمی‌شود.
3. اگر تگ تازه‌تر از `version.json` بود (و نسخهٔ نصب‌شده از همان تگ ساخته نشده
   باشد — با مقایسهٔ `tag` در `version.json`، تا برچسب‌هایی مثل `build-42`
   بی‌پایان دوباره پیشنهاد نشوند)، `update-manifest.json` گرفته و با sha256
   فایل‌های نصب مقایسه می‌شود.
4. دانلود خودکار (پیش‌فرض روشن، `autoDownload`): رابط به‌محض دیدن نسخهٔ تازه بستهٔ
   تغییرات را **یک بار** می‌گیرد؛ برای هر نسخه فقط یک تلاش انجام می‌شود و از تنظیمات
   آپدیت هم می‌توان خاموشش کرد (آن‌وقت دکمهٔ «دریافت آپدیت» ظاهر می‌شود).
   مسیر دانلود: `update-<tag>.zip` → بررسی sha256 هر فایل → اگر فایلی در دلتا نبود، از بستهٔ
   کامل گرفته می‌شود → `pending.json` نوشته می‌شود. هش نامطابق = خطای صریح و
   `pending.json` ساخته نمی‌شود.
5. اعمال: اگر کاربر دکمهٔ «اعمال و راه‌اندازی مجدد» را بزند، همان لحظه؛ وگرنه
   آپدیت دانلودشده در **اجرای بعدی** برنامه، پیش از بالا آمدن سرور، خودکار اعمال
   می‌شود (میزبان دسکتاپ این را انجام می‌دهد).
   `T4Translate.exe` در حال اجرا قابل جایگزینی نیست. برنامه
   `apply-update.cmd` را می‌سازد، می‌بندد و پس از خروج، اسکریپت ابتدا **هر فایلی را که
   جایگزین می‌شود** در `updates/backup/<version>/` کپی می‌کند، بعد با `robocopy`
   فایل‌های تازه را می‌نویسد، فایل‌های حذف‌شده را پاک می‌کند، `pending.json` را برمی‌دارد
   و دوباره `T4Translate.exe` را اجرا می‌کند.

پوشهٔ داده: `<T4_DATA_DIR>/updates/` شامل `stage/`، `downloads/`، `pending.json`،
`apply-request.json`، و `update-state.json` / `update-settings.json` (مجوز ۶۰۰).

## محدودیت پلن رایگان GitHub

- درخواست بی‌توکن به API: **۶۰ درخواست در ساعت برای هر IP**. با فاصلهٔ ۱۰ ثانیه،
  همین سهمیه در ۶ دقیقه تمام می‌شود و برنامه برای بقیهٔ ساعت خطای ۴۰۳ می‌گیرد.
  پس ۱۰ ثانیه فاصلهٔ **رابط** است، نه GitHub.
- با توکن (پلن رایگان، `repo` برای مخزن خصوصی): **۵۰۰۰ درخواست در ساعت**.
  فاصلهٔ ۳۰۰ ثانیه‌ای = ۱۲ درخواست در ساعت، یعنی زیر ۰٫۳٪ سهمیه.
- حداقل‌ها در کد اعمال می‌شوند: `MIN_CHECK_SECONDS_ANONYMOUS = 60` و
  `MIN_CHECK_SECONDS_TOKEN = 20`؛ مقدار کمتر در تنظیمات پذیرفته نمی‌شود.
- سرصفحه‌های `X-RateLimit-Remaining` و `X-RateLimit-Reset` ذخیره می‌شوند؛ وقتی سهمیه
  ته کشیده باشد بررسی (حتی بررسی دستی) تا زمان reset انجام نمی‌شود و رابط پیام
  «سهمیهٔ GitHub تمام شده» نشان می‌دهد.
- دانلود دارایی یک ریلیز در مخزن خصوصی هم به توکن نیاز دارد؛ بدون آن خطای فارسی
  صریح نمایش داده می‌شود و برنامه در حلقهٔ تلاش نمی‌افتد.
- ترتیب دانلود هر دارایی: اول `browser_download_url`؛ اگر ۴۰۴/۴۰۳ بدهد، همان فایل از
  آدرس API (`/releases/assets/<id>` با `Accept: application/octet-stream`) و با توکن
  گرفته می‌شود. خطا نام فایل و علت را نشان می‌دهد، نه پیام مبهم.

## توکن

توکن هرگز در مخزن یا داخل exe جاسازی نمی‌شود. یکی از این دو:

- متغیر محیطی `T4_UPDATE_TOKEN` (و اختیاری `T4_UPDATE_REPO`)؛
- یا در «تنظیمات آپدیت» داخل برنامه، که در `update-settings.json` با مجوز ۶۰۰ ذخیره
  می‌شود و `GET /api/update/settings` فقط `hasToken: true` را برمی‌گرداند، نه خود توکن.

توکن پیشنهادی: fine-grained token با دسترسی **فقط‌خواندنی** روی همین مخزن
(Contents: Read). برای مخزن عمومی اصلاً لازم نیست.

## انتشار یک نسخهٔ تازه

```bash
git tag v0.1.3 && git push origin v0.1.3
```

CI (ویندوز) این‌ها را انجام می‌دهد: تست‌ها و build، ساخت exe، نوشتن `version.json`،
smoke test بسته، ساخت zip کامل، ساخت `update-manifest.json` و `update-<tag>.zip`
نسبت به ریلیز قبلی، و `gh release create` با هر سه فایل. اگر smoke test رد شود،
ریلیزی منتشر نمی‌شود.

`workflow_dispatch` هم یک ریلیز `build-<run_number>` می‌سازد (برای آزمون) و آن را
`prerelease` علامت می‌زند؛ ریلیزهای prerelease در «آخرین ریلیز» نمی‌آیند، پس کاربران
عادی فقط نسخه‌های تگ‌دار را آپدیت می‌بینند.

## آزمون دستی

- `GET /api/update/status` باید `channel:"release"`، `checkSeconds`، `pollSeconds` و
  `updateAvailable` را بدهد.
- `POST /api/update/check` بررسی فوری است ولی مثل بقیه از سهمیه و حداقل فاصله
  پیروی می‌کند.
- `POST /api/update/download` فقط وقتی آپدیت موجود است کار می‌کند.
- `DELETE /api/update/pending` آپدیت دانلودشده را دور می‌ریزد.
- آزمون‌ها: `backend/tests/test_updater.py` (۱۹ تست، با HTTP جعلی) و
  `backend/tests/test_update_manifest.py` (۴ تست برای دلتا).

## محدودیت‌های شناخته‌شده

- امضای کد و نصب‌کننده وجود ندارد؛ exe بدون امضا اجرا می‌شود و ویندوز ممکن است
  هشدار SmartScreen بدهد.
- بازگشت خودکار (دکمهٔ «برگرداندن نسخهٔ قبلی») پیاده نشده است. فایل‌های جایگزین‌شده
  در `updates/backup/<version>/` هستند و برگرداندن دستی یعنی کپی همان‌ها روی پوشهٔ نصب؛
  راه ساده‌تر: بستهٔ کامل نسخهٔ دلخواه را از Releases بگیرید و روی همان مسیر باز کنید.
- مسیر اعمال آپدیت روی ویندوز واقعی و PyInstaller آزموده نشده است.
