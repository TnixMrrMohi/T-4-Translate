# نقشهٔ اجرای بازسازی

## مرحله صفر: استخراج قرارداد از پروژهٔ قدیمی
- پروژهٔ اصلی و این مستندات را در اختیار ایجنت بگذار. `appsettings.json`, controllers، کلاس‌های domain، testها و UI را بررسی کند. با .NET و مدل‌های صحیح، نمونه‌های واقعی برای هر گردش و error تهیه کند؛ تفاوت README/کد، نسخهٔ مدل و مجوز ثبت شوند.
- برای تک‌تک endpointها schema/body/result/status واقعی را در یک contract قابل اجرا استخراج و درستی آن را با تست تضمین کن. این سند عمداً جایگزین آن spec ریزدانه نیست.

## مراحل تحویل
1. اسکلت FastAPI/React، health، فایل‌سیستم ایمن، config و UI RTL، CI و mockهای تست.
2. job queue + lifecycle + آپلود + مدل داده و workspace؛ import/export و recovery قابل تست.
3. image operations + YOLO + PaddleOCR + اسکن بیرون حباب و خروجی OCR؛ ارزیابی با مدل واقعی.
4. parser ترجمه و prefill داستان + park/resume و حفاظت concurrent؛ سپس LaMa/fallback و رندر فارسی.
5. editor، پیش‌نمایش، تک‌بلاک، تمام نماهای نتیجه و بستهٔ صفحه.
6. batch کامل و قدیمی، ZIP امن، story/chapter/terms، import/export و سازگاری.
7. hardware/settings، کیفیت، امنیت، تست performance، بستهٔ دسکتاپ، نصب مدل و migration ابزار.
در پایان هر مرحله یک vertical slice قابل اجرا و acceptance tests ارائه کن؛ فهرست ردیابی ویژگی → فایل مرجع → آزمون → وضعیت داشته باش.

## تصمیم‌هایی که بدون کاربر قطعی نیست
- سازگاری اجباری API، schema و package v1 یا فقط مهاجرت؟ پشتیبانی همزمان SQL Server؟
- اولویت حفظ ظاهر دقیق در برابر بازطراحی؟ ویندوز تنها یا Linux/macOS نیز؟
- سخت‌افزار هدف، حد RAM، زمان پردازش و کیفیت قابل قبول، corpus مرجع و مجوز آن؟
- داده‌های برنامهٔ قبلی و jobهای پارک‌شده نیاز به مهاجرت دارند؟
- مدل‌ها و فونت‌ها و لایسنس‌های مجاز برای انتشار؟ دانلود/آفلاین؟
- دسترسی sandbox فقط برای توسعه یا سرویس اشتراکی؟ بودجه و الزام‌های احراز هویت؟

## درخواست پیشنهادی برای ایجنت
«این مجموعه و سورس commit مشخص‌شده را بخوان، ابتدا قراردادهای ریز و تست‌های نمونه را از منبع استخراج کن، شکاف‌ها و تصمیم‌ها را ثبت کن. سپس برنامه را طبق مراحل بساز؛ قابلیت قبلی را حذف نکن، پیشنهاد را با رفتار موجود اشتباه نگیر، و با داده/مدل واقعی و گزارش تست تحویل بده.»
