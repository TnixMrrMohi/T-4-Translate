# راهنمای بازسازی MangaPars با Python و TypeScript

## مأموریت ایجنت سازنده
برنامهٔ موجود در همین مخزن را به یک اپلیکیشن محلی ترجمه و ویرایش مانگا/وب‌تون با **Python + FastAPI**، **TypeScript + React** و موتورهای پردازش native بازسازی کن. هدف، حفظ قابلیت‌های فعلی، داده‌ها و تجربهٔ فارسی و سپس افزودن بهبودهای مشخص‌شده است؛ صرفاً ساخت یک دموی OCR یا mock قابل قبول نیست. این مجموعه نقشهٔ اجرایی است و به‌تنهایی جایگزین تمام جزئیات ۲۹ هزار خط کد، تست‌ها و منابع اصلی نیست: **ایجنت باید مخزن اصلی را در کنار این اسناد داشته باشد** و در موارد قرارداد دقیق به فایل مرجع و تست ارجاع‌شده مراجعه کند.

## قواعد تصمیم‌گیری
- برچسب «موجود» = رفتار قابل استناد به کد؛ «هدف» = طراحی پیشنهادی، نه ادعای وجود در برنامه. در تعارض: تست معتبر + کد اجرایی > `appsettings.json` برای تنظیمات اجرا > README > این خلاصه. ناسازگاری‌ها را ثبت و با کاربر حل کن، نه اینکه بی‌صدا حذف کنی.
- سازگاری رفتاری و داده مهم‌تر از بازتولید پیاده‌سازی C# است؛ تفاوت بیت‌به‌بیت خروجی مدل‌ها و فونت‌ها را تضمین نکن. برای API و فایل‌ها آزمون قراردادی و در صورت تغییر نسخه، adapter/مهاجرت بده.
- هیچ API ابری یا کلیدی برای جریان پیش‌فرض لازم نباشد؛ ترجمه با کپی/پیست کاربر است. مدل OCR انگلیسی پیش‌فرض است، نه OCR همهٔ زبان‌ها.
- قابلیت‌ها را مرحله‌ای و قابل اجرا بساز؛ از mock فقط در تست استفاده کن. کاربر بتواند مدل‌ها را نصب کند و فقدان آنها و fallbackها را ببیند.
- نیاز امنیتی فعلی: تک‌کاربر، روی ماشین محلی، بدون احراز هویت؛ سرویس را به شبکه عمومی باز نکن. اجرای پشت preview sandbox نیازمند پیکربندی و کنترل امنیت جداگانه است.
